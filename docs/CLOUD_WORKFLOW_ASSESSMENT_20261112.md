## 最小延續方案

1. 繼續從同一Work雲端環境操作原repo；每次先取得main、讀AGENTS及當隊進度。保持本次已可用的GitHub、Gmail及研究指引連線，毋須先換託管平台。
2. 在乾淨工作目錄建立專屬分支，依據日期明確的官方來源研究；完成完整登錄／近期名單比對，區分登錄、盃賽資格與當場選拔。資料不足就保存具名缺口。
3. 跑npm test、相關球會嚴格驗證及本場關鍵事實／連結檢查；提交到原repo，以expected_sha更新main，避免覆蓋別人的新提交。
4. 讀部署結果並在雲端瀏覽器驗證正式頁。對不確定是否已執行的操作先查結果；被拒後不得原樣反覆重試。
5. 每次在repo留下可恢復的來源、研究狀態、檢查結果、commit及正式URL。另一雲端工作目錄可從main還原；原聊天可繼續使用。
